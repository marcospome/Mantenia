Defensa del TP: MantenIA

Sistema de mantenimiento predictivo para plantas industriales y talleres. Una API REST en .NET documentada con OpenAPI (Swagger) y una app web mobile que la consume. Esta guía enseña .NET desde cero y después recorre el proyecto archivo por archivo, para que cualquiera del equipo pueda explicarlo y modificarlo.

Entidad principal: Activo Entidad de relación: Cliente (y Orden de trabajo) Tema de investigación: API y Swagger Stack: .NET 10 · EF Core · SQL Server · React

01El proyecto en 1 minuto

MantenIA registra los activos de una organización (compresores, bombas, tornos o, en un taller mecánico, vehículos) y las órdenes de trabajo que se les hacen. Con ese historial calcula indicadores como el MTBF (tiempo medio entre fallas) y avisa qué equipo tiene más probabilidad de romperse.

CarpetaQué esTecnología
Mantenia.Api/El backend: recibe pedidos HTTP, aplica las reglas de negocio y lee/escribe la base. Se documenta sola con OpenAPI.ASP.NET Core 10, Entity Framework Core, SQL Server, JWT
mantenia-app/El frontend: la pantalla que usa el operario desde el celular o la PC. Todo lo que muestra se lo pide a la API.React 19 + TypeScript, Vite, Tailwind
🍽️
Ejemplo del día a día: un restaurante

El cliente en la mesa es la app React. El mozo es el Controller: toma el pedido, revisa que esté completo y lo lleva a la cocina. La cocina es el Service: sabe las recetas (reglas de negocio). La despensa es la base de datos, y el ayudante que trae los ingredientes es Entity Framework. La carta que dice qué se puede pedir y cómo es Swagger/OpenAPI.

El cliente nunca entra a la cocina ni a la despensa: solo habla con el mozo, usando lo que dice la carta.

Separamos backend y frontend porque el tema que investigamos es API y Swagger. La misma API la puede usar nuestra app web, una app nativa o cualquier otro sistema, y Swagger la documenta y permite probarla sin escribir código.

03¿Qué es .NET?

Un programa es una lista de instrucciones que la computadora ejecuta. Esas instrucciones se escriben en un lenguaje de programación. Para el backend de MantenIA usamos el lenguaje C# (se pronuncia “ce sharp”) sobre la plataforma .NET (“dot net”), ambos de Microsoft.

🌎
Ejemplo del día a día: un país

C# es el idioma en el que escribimos. .NET es el país donde ese idioma funciona: tiene sus leyes (cómo se ejecuta un programa), sus servicios públicos (miles de funciones ya hechas para leer archivos, manejar fechas, conectarse a internet) y sus herramientas (el compilador, el comando dotnet). ASP.NET Core es una ciudad de ese país especializada en hacer sitios web y APIs, y Entity Framework Core es la oficina que se encarga de hablar con la base de datos.

¿Qué pasa cuando “ejecutamos” la API?

La computadora no entiende C# directamente. El código pasa por varias etapas:

→

  1. Compilar es traducir el código escrito por personas a algo que la máquina pueda ejecutar. Si hay un error de escritura (falta un ;, una variable no existe), el compilador avisa y no deja seguir. Esto evita muchos errores antes de ejecutar.
  2. El resultado es un archivo .dll en la carpeta bin/. No hay que tocarlo: se regenera cada vez que compilamos.
  3. El runtime (CLR, Common Language Runtime) carga ese .dll y lo ejecuta. También libera la memoria que ya no se usa (el “recolector de basura”), así no tenemos que hacerlo a mano.

.NET Framework vs .NET. Hay dos “familias”. .NET Framework (hasta la 4.8) es la vieja, solo para Windows. .NET a secas (antes “.NET Core”, versiones 5, 6, 7, 8, 9, 10) es la moderna y multiplataforma.   • Usamos .NET 10, versión moderna y multiplataforma.

Una variable es una caja con nombre donde guardamos un dato. En C# cada caja tiene un tipo que dice qué se puede guardar adentro. Si intentás guardar un texto en una caja de números, el compilador no te deja.

2 string nombre = "Compresor C-02";

null y el signo ?

null significa “no hay nada”. En la base de datos es una columna vacía. En C#, un tipo seguido de ? acepta null; sin ?, no.

public int IdActivo { get; set; }          // siempre tiene número
public int? IdCliente { get; set; }        // puede no tener cliente → null
public string? Marca { get; set; }         // la marca es opcional
📦
Ejemplo del día a día: un formulario en papel

Un casillero vacío no es lo mismo que un casillero con un 0. Si en “cantidad de hijos” ponés 0, es un dato; si lo dejás en blanco, no sabemos. null es el casillero en blanco.

Usar algo que es null como si tuviera valor hace que el programa falle con el error más famoso de C#: NullReferenceException. Por eso C# tiene operadores para manejar null con cuidado. Todos aparecen en el proyecto:

OperadorSe leeEjemplo real
??“si lo de la izquierda es null, usá lo de la derecha”usuario.Email ?? string.Empty → si no tiene email, texto vacío
?.“si no es null, seguí; si es null, devolvé null”a.Cliente?.Nombre → si el activo no tiene cliente, no explota
??=“asignale este valor solo si todavía está en null”orden.FechaInicio ??= ahora; → la fecha de inicio se pone una sola vez
! (al final)“compilador, confiá: esto no es null”conFecha[0].FechaCreacion!.Value
is null / is not nullpregunta si es nullreturn dto is null ? NotFound() : Ok(dto);

07C# desde cero (2): clases y objetos

C# es un lenguaje orientado a objetos: el programa se arma con piezas llamadas clases. Una clase es un molde que define qué datos tiene algo y qué puede hacer. Un objeto es una pieza concreta hecha con ese molde.

🍪
Ejemplo del día a día: el molde de galletitas

La clase Activo es el molde: dice que todo activo tiene nombre, marca, modelo. Cada activo real (“Compresor C-02”, “Torno T-04”) es una galletita hecha con ese molde: un objeto. Con un molde podés hacer miles de galletitas, cada una con sus propios valores.

Métodos: lo que una clase sabe hacer

Un método es un bloque de código con nombre que recibe datos (parámetros), hace algo y puede devolver un resultado.

1 private static string? Texto(string? valor)
  {
2     if (string.IsNullOrWhiteSpace(valor))
          return null;
3     return valor.Trim();
  }

4 private static string? Texto(string? valor) => string.IsNullOrWhiteSpace(valor) ? null : valor.Trim();
  1. Se lee: método privado, estático, que devuelve string?, se llama Texto y recibe un parámetro valor.

🚕

Lambdas: funciones cortitas

Una lambda es una función sin nombre escrita en una línea con la flecha =>. A la izquierda va lo que recibe, a la derecha lo que devuelve.

a => a.Nombre                              // “dado un activo a, devolvé su nombre”
a => a.IdOrganizacion == org               // “dado un activo a, ¿es de mi organización?” (true/false)
(x, y) => x + y                            // dos parámetros

LINQ: preguntarle cosas a una colección

LINQ (Language Integrated Query) es un conjunto de métodos para filtrar, ordenar y transformar listas. Reciben lambdas. Es lo que más se usa en el proyecto.

🛒
Ejemplo del día a día: filtrar en una tienda online

“Mostrame las zapatillas (Where) de talle 42, ordenadas por precio (OrderBy), solo nombre y precio (Select), las primeras 10 (Take)”. LINQ es exactamente eso, escrito en código.

var activos = new List<Activo> { ... };

activos.Where(a => a.Marca == "Atlas Copco")        // filtra: solo los Atlas Copco
activos.Select(a => a.Nombre)                         // transforma: de cada activo, solo el nombre
activos.OrderBy(a => a.Nombre)                        // ordena A→Z
activos.Any(a => a.IdActivo == 5)                     // ¿hay alguno? → true/false
activos.Count(a => a.IdCliente != null)               // ¿cuántos tienen cliente?
activos.First(a => a.IdActivo == 5)                   // el primero que cumpla (error si no hay)
activos.FirstOrDefault(a => a.IdActivo == 5)          // el primero o null si no hay
activos.Sum(r => r.Costo)                             // suma
activos.ToList()                                      // ejecuta y devuelve una lista

Se pueden encadenar, uno detrás del otro, como en ListarAsync:

var ordenados = items
    .Where(a => a.Salud.Nivel == "riesgo")
    .OrderBy(a => a.Nombre)
    .ToList();

Excepciones: cómo se avisa que algo salió mal

Cuando algo falla, C# lanza una excepción (throw). La ejecución se corta y la excepción “sube” hasta que alguien la atrapa (catch). Si nadie la atrapa, el programa falla.

1 public sealed class ConflictException(string message) : Exception(message);

  if (ordenes > 0)
2     throw new ConflictException("No se puede eliminar: tiene órdenes.");

  try
  {
3     return _hasher.VerifyHashedPassword(usuario, hash, clave) != PasswordVerificationResult.Failed;
  }
4 catch (FormatException)
  {
      return false;
  }
  1. Creamos nuestra propia excepción heredando de Exception. La usamos para “regla de negocio violada”.
  2. throw la lanza: el método se corta ahí.
  3. try: “intentá esto”.
  4. catch: “si falló con este tipo de error, hacé esto otro en vez de explotar”.

En la API, las excepciones que nadie atrapa las agarra un manejador global y las convierte en una respuesta JSON (lo vemos en “Manejo de errores”).

Ir a la base de datos tarda (milisegundos, pero para una computadora es muchísimo). Si la API se quedara “congelada” esperando, no podría atender a otros usuarios mientras tanto.

🍔
Ejemplo del día a día: el local de hamburguesas

Pedís, te dan un número y te corrés. El cajero atiende al siguiente mientras cocinan lo tuyo. Cuando está listo, te llaman. El número es el Task, correrte a esperar es el await, y el cajero que sigue atendiendo es el servidor, que no se bloquea.

  {
      ...
2     await db.SaveChangesAsync(ct);
3     return new ClienteDto(...);
  }
  1. async marca que el método tiene esperas adentro. Devuelve Task<ClienteDto>: “una tarea que en algún momento va a dar un ClienteDto”. Por convención el nombre termina en Async.
  2. await = “esperá a que esto termine, pero liberá el hilo mientras tanto”.
  3. Cuando vuelve la base, sigue en la línea siguiente como si nada.

CancellationToken ct: aparece como último parámetro en casi todos los métodos. Si el usuario cierra la app a mitad de un pedido, ASP.NET “cancela” ese token y las consultas pendientes se cortan, sin gastar recursos de más.

  • throw lanza un error; try/catch lo atrapa.

11Cómo funciona la web: HTTP, REST y JSON

¿Qué es una API REST?

Una API (Application Programming Interface) es un contrato para que un programa use a otro. Una API REST usa HTTP, el mismo protocolo de las páginas web, con tres ideas:

  1. Recursos con dirección. Cada cosa del sistema tiene una URL: /api/app/activos es “todos los activos”, /api/app/activos/15 es “el activo 15”.
  2. El verbo dice la acción. La misma URL hace cosas distintas según el verbo: GET lee, POST crea, PUT modifica, DELETE borra. Es el ABM (CRUD) de la consigna.
  3. Sin estado. El servidor no “recuerda” al usuario entre pedidos. Cada pedido trae todo lo necesario, incluido el token que dice quién es.
📮
Ejemplo del día a día: el correo

La URL es la dirección del sobre. El verbo es el tipo de trámite (consultar, enviar, modificar, dar de baja). El cuerpo JSON es la carta. Los headers son lo que va escrito en el sobre (remitente, tipo de contenido). Y el código de respuesta es el sello que vuelve: entregado, dirección inexistente, falta firma.

      ALTER TABLE dbo.Activo ADD IdOrganizacion INT NULL;
  GO
2 IF NOT EXISTS (SELECT 1 FROM sys.foreign_keys WHERE name = 'FK_Activo_Organizacion')

          FOREIGN KEY (IdOrganizacion) REFERENCES dbo.Organizacion (IdOrganizacion);
  GO
3 UPDATE a SET a.IdOrganizacion = COALESCE(c.IdOrganizacion, cl.IdOrganizacion)
  FROM dbo.Activo a
  LEFT JOIN dbo.CategoriaActivo c ON c.IdCategoriaActivo = a.IdCategoriaActivo
  LEFT JOIN dbo.Cliente cl ON cl.IdCliente = a.IdCliente
  WHERE a.IdOrganizacion IS NULL;

De LINQ a SQL

Lo que escribimos en C# y lo que EF le manda a SQL Server (aproximado):

C# (LINQ)
await db.Clientes.AnyAsync(c =>
    c.IdCliente == idCliente &&
    c.IdOrganizacion == org, ct);
SQL generado
SELECT CASE WHEN EXISTS (
  SELECT 1 FROM dbo.Cliente c
  WHERE c.IdCliente = @p0
    AND c.IdOrganizacion = @p1)
THEN 1 ELSE 0 END
C# (LINQ)
db.Activos.Add(activo);
await db.SaveChangesAsync(ct);
SQL generado
INSERT INTO dbo.Activo
  (IdOrganizacion, Nombre, Marca, ...)
OUTPUT INSERTED.IdActivo
VALUES (@p0, @p1, @p2, ...)

Los valores viajan como parámetros (@p0), nunca pegados en el texto. Por eso EF nos protege de inyección SQL.

Tres detalles que aparecen en todo el código

  1. async / await: mientras la base responde, el hilo queda libre para atender otro pedido. Es como un local de comida rápida: te dan un número y no bloqueás la caja mientras cocinan.
  2. CancellationToken ct: si el usuario cierra la app a mitad de un pedido, la consulta se cancela y no gasta recursos.
  3. AsNoTracking(): para consultas de solo lectura le decimos a EF que no vigile cambios en esos objetos. Es más rápido.
  • DbContext es la puerta a la base; cada DbSet<T> es una tabla.
  • Las clases de Data/Configurations describen nombre, PK, largos y relaciones de cada tabla.
  • LINQ sobre db.Tabla se traduce a SQL con parámetros (protege de inyección SQL).

25Lógica propia: el cálculo del MTBF

La base no tiene columnas de “probabilidad de falla”: la API la calcula con el historial de órdenes en Services/App/Indicadores.cs.

🚗
Ejemplo del día a día: el auto que se rompe seguido

Si tu auto se quedó 2 veces en 90 días, en promedio se rompe cada 45 días. Si ya pasaron 39 días desde la última vez, es lógico pensar que está por fallar de nuevo. Eso es el MTBF (Mean Time Between Failures).

1 var fallas = conFecha.Where(EsFalla).ToList();
  if (fallas.Count > 0)
  {
      var primera = conFecha[0].FechaCreacion!.Value;
2     var observados = Math.Max(1, (ahora - primera).TotalDays);
      mtbf = Math.Max(1, observados / fallas.Count);

3     var ultimaFalla = fallas[^1].FechaCreacion!.Value;
      var desde = Math.Max(0, (ahora - ultimaFalla).TotalDays);
      diasProxima = (int)Math.Max(0, Math.Round(mtbf.Value - desde));
4     probabilidad = (int)Math.Clamp(Math.Round(100 * desde / mtbf.Value), 0, 99);
  }
5 var nivel = probabilidad >= 80 ? "riesgo" : probabilidad >= 60 ? "revisar" : "ok";
  1. Una orden cuenta como falla si su tipo de trabajo no es preventivo. Es preventivo si el nombre contiene palabras como “service”, “inspección”, “lubricación”, “aceite”, “filtro”…
  2. Días observados desde la primera orden ÷ cantidad de fallas = MTBF.
  3. fallas[^1] es el último elemento de la lista (índice desde el final).
  4. Probabilidad = qué porcentaje del MTBF ya pasó desde la última falla. Clamp la limita entre 0 y 99.
  5. Ternario encadenado: 80 % o más es riesgo; 60 % o más, revisar.

No es inteligencia artificial: es una regla estadística simple sobre el historial. La elegimos porque se puede explicar y verificar a mano.
  • MTBF = días observados ÷ fallas. Probabilidad = días desde la última falla ÷ MTBF.
  • 60 % o más: revisar. 80 % o más: en riesgo.

35Preguntas probables

¿Por qué una API y no MVC directo?

Porque el tema de investigación es API y Swagger. Separar la API permite que la use cualquier cliente (web, mobile, otro sistema), que quede documentada con OpenAPI y que la lógica de negocio esté en un solo lugar.

¿Qué diferencia hay entre una entidad y un DTO?

La entidad representa la tabla y la usa EF Core. El DTO es lo que entra o sale por la API: solo los campos necesarios y con data annotations. Así no exponemos la estructura de la base ni aceptamos campos como IdOrganizacion.

¿Qué es la inyección de dependencias y para qué sirve?

Las clases piden lo que necesitan en el constructor (por interfaz) y el framework se lo entrega. Desacopla las capas, facilita testear y cambiar implementaciones. Se configura en ServiceCollectionExtensions.cs.

¿Qué diferencia hay entre Scoped y Singleton?

Singleton: una instancia para toda la app (la usamos en TokenService, que no guarda estado). Scoped: una por pedido HTTP (servicios de negocio y DbContext, porque cada pedido tiene su usuario y su conexión).

¿Dónde se valida y qué pasa si falla?

Formato: data annotations del DTO, validadas por [ApiController] antes de entrar al método → 400. Reglas de negocio: en el servicio, con ConflictException → 409 vía GlobalExceptionHandler.

¿Qué es un middleware?

Un paso del recorrido que hace cada pedido (autenticación, autorización, manejo de errores, CORS). Se ejecutan en el orden en que se registran en Program.cs y cualquiera puede cortar el recorrido.

¿Cómo se guarda la contraseña?

Con hash PBKDF2 + HMAC-SHA512, sal aleatoria y 100.000 iteraciones (el PasswordHasher de ASP.NET Identity). Nunca en texto plano y nunca se devuelve.

¿Qué es un JWT? ¿Se puede falsificar?

Un token con encabezado, datos y firma. Los datos se pueden leer pero no modificar: la firma se calcula con una clave que solo tiene la API. Si cambian algo, la firma no coincide y se rechaza.

¿Qué diferencia hay entre 401 y 403?

401: no sabemos quién sos (sin token o token inválido). 403: sabemos quién sos pero tu rol no tiene permiso para esa acción.

¿Por qué los permisos se leen de la base y no del token?

Para que un cambio de rol o de permisos aplique en el siguiente pedido, sin esperar 24 horas a que venza el token.

¿Cómo evitan que un usuario vea datos de otra empresa?

Todas las consultas de activos parten de DatosOrganizacion.ActivosQuery(), que filtra por la organización del usuario. Un id ajeno da 404.

¿Qué es Entity Framework? ¿Por qué no hay migraciones?

Un ORM que traduce LINQ a SQL parametrizado (protege de inyección SQL). La base ya existía, así que la mapeamos con Fluent API en vez de generarla desde el código. Los cambios están en Scripts/*.sql.

¿Para qué sirve async/await?

Mientras se espera a la base, el hilo queda libre para atender otros pedidos. Con pocos hilos la API atiende muchos usuarios a la vez.

¿Swagger y OpenAPI son lo mismo?

OpenAPI es el estándar (el JSON). Swagger UI y Scalar son interfaces que lo leen. Usamos Scalar porque .NET 9+ ya no trae Swashbuckle, pero el documento es el mismo.

¿Cómo calculan el MTBF?

Días desde la primera orden ÷ cantidad de fallas. La probabilidad es qué porcentaje del MTBF pasó desde la última falla; 60 % es “revisar”, 80 % “en riesgo”. Está en Indicadores.cs.

¿Qué pasa si se cae la base?

EF lanza una excepción, el GlobalExceptionHandler la registra en el log y responde 500 con un mensaje genérico, sin exponer detalles técnicos.

¿Qué es .NET y qué es C#?

C# es el lenguaje en el que escribimos. .NET es la plataforma que lo compila y ejecuta, con librerías ya hechas. ASP.NET Core es la parte de .NET para hacer APIs, y EF Core la parte para la base de datos.

¿Qué es una interfaz y por qué la usan?

Un contrato con la lista de métodos, sin código. ActivosAppService implementa IActivosAppService. El controller depende del contrato, no de la clase, así se puede cambiar la implementación sin tocarlo.

¿Qué es LINQ?

Métodos de C# para consultar colecciones (Where, Select, OrderBy). Sobre las tablas de EF Core se traducen a SQL y se ejecutan en la base.

¿Qué hace exactamente [ApiController]?

Valida el DTO con sus data annotations antes de entrar al método y, si falla, responde 400 con el detalle de cada campo. También infiere que los objetos complejos vienen del cuerpo JSON.

¿Cómo agregarían un campo nuevo?

Columna en la base, propiedad en la entidad, propiedad con validación en el DTO, copiarla en el servicio, agregarla al DTO de respuesta y al formulario. El controller no cambia (ver la receta).

¿Qué pasa si dos usuarios guardan a la vez?

Cada pedido tiene su propio DbContext (Scoped) y SQL Server maneja la concurrencia. Gana el último que guarda; para este alcance no hace falta control optimista.
